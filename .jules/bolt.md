## 2025-02-19 - O(N²) nested loops in CalendarGrid memoized values
**Learning:** In the `CalendarGrid` component, iterating over `departments` and then `requests` inside a `useMemo` block creates an O(D * R) complexity. In applications with many departments and vacation requests, this can become a significant performance bottleneck during rendering.
**Action:** Always prefer building an intermediate lookup map (e.g., `Map<userId, departmentIds>`) in O(U) time, and then process the requests in O(R) time by looking up the department IDs from the map. This brings the complexity down to O(U + R). Note that since a user might theoretically belong to multiple departments in the data structures (or to handle mapping properly), use `Map<string, string[]>` instead of a strict 1-to-1 mapping to avoid regressions.

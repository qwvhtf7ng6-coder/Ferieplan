## 2024-03-20 - [O(N) Hash Map Optimization for Many-to-Many Mappings]
**Learning:** When optimizing nested O(N²) array lookups involving users and departments in the frontend using O(N) hash maps, you must account for cases where users may belong to multiple departments by mapping users to an array of ids `Map<string, string[]>` rather than just one ID. Additionally, directly mutating dates with substring can lead to timezone issues if you skip normalisation, meaning it is often safer to pay the cost of `new Date(date).toISOString().slice(0,10)`.
**Action:** When implementing O(1) lookups to replace array filtering methods (like `some()`), verify whether the relationship is strictly 1:1 or 1:N before selecting the hash map value type (`string` vs `string[]`). And never optimise out correct date timezone parsing just to save an instantiation, unless you are strictly guaranteeing the input format.

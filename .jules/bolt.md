## 2025-02-12 - Optimizing Date parsing and array iteration in React useMemo
**Learning:** React `useMemo` calculation logic gets very slow if we parse `Date` objects repeatedly during array iterations (e.g. `new Date(h.date).toISOString()`) vs handling ISO string slicing correctly. Nested `Array.some` iterations in combination with `Date` parsing on large multi-tenant datasets (e.g. departments x users x requests x days) can cause severe main-thread blocks. Also, Prisma / API boundary strings must be handled defensively since Date objects may arrive dynamically. Modifying `package.json` to add an eslint plugin when running lint checks can be dangerous because of strict repo constraints.
**Action:** When building nested view structures in frontend elements like `CalendarGrid`, map user-relationships to `HashMap/Map` in `O(N)` first, then execute data lookups with `O(1)` map keys. Check if Date objects are strings before processing, and revert any automated tsconfig or package.json changes before commiting.
